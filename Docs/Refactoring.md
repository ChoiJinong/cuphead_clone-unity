# C# 리팩터링 기록

## 범위와 보존 기준

작업 시작 시 Git 작업 트리는 깨끗했습니다. `Assets/@Scripts`의 14개 런타임 스크립트와 기존 검증 스크립트 1개를 검토했습니다.

직렬화 필드의 이름·타입·기본값, 스크립트 GUID, 씬·프리팹·Animator·애니메이션 연결은 유지했습니다. 따라서 Inspector 값을 다시 연결할 필요가 없습니다. `PlayerAttack` 클래스명도 유지합니다.

## 주요 변경

| 코드 | 변경 이유 |
|---|---|
| PlayerController / PlayerMovement | 이동이 공격 컴포넌트를 직접 참조하던 순환 의존성을 제거했습니다. Controller가 조준·앉기 입력을 물리 업데이트에 전달합니다. |
| PlayerMovement | 물리 처리의 흐름을 이동·점프, 대시 진행, 대시 속도 계산으로 나눴습니다. 기존 계산식과 입력 처리 시점은 유지했습니다. |
| PlayerAttack | 방향 입력, 앉기 전환, 공격 클립 선택을 구분했습니다. Blend Tree의 0~6 선택값에 이름을 붙였습니다. 실제 발사도 계속 이 클래스가 담당합니다. |
| PlayerBullet | 비행 검사, 충돌 지점 검색, Hit 재생 종료, 물리 정지를 나눴습니다. 충돌·반환·중복 반환 방지 동작은 유지했습니다. |
| PlayerBulletSpark | 재생 종료 조건과 복귀 안전 시간을 구분하고 상태 변수 이름을 정리했습니다. |
| BulletPool | ObjectPool 생성자의 인자 이름을 명시해 생성·반환·폐기 콜백의 역할을 바로 읽을 수 있게 했습니다. 별도 풀 추상화는 추가하지 않았습니다. |
| SceneManager | 현재 씬 종류를 처음 조회할 때도 CurrentScene을 통해 장면을 찾도록 수정했습니다. Unity의 동명 SceneManager는 별칭으로 구분합니다. |
| Singleton | 접근 제한자와 필드·지역 변수 이름을 정리했습니다. 기존 생성·유지 방식은 같습니다. |
| ResourceManager / Utils / Extension / Define / LoadingScene | 빈 Start·Update, 사용하지 않는 using, 깨진 주석을 정리했습니다. 유틸리티 컨테이너는 static으로 명시했습니다. |
| BaseScene | 기존의 SceneType과 파생 씬용 Awake 구조가 명확하므로 변경하지 않았습니다. |

애니메이션 오류 시 풀로 돌아오지 않는 문제를 막는 제한 시간과, 여러 충돌 콜백에 따른 중복 반환 방지는 필요한 방어 코드이므로 유지했습니다.

## 실행 흐름

- `PlayerController.Awake`: Movement와 Attack을 명시적으로 초기화합니다.
- `Update`: 이동 입력 → 공격·조준 입력에 따른 이동 제한 → 이동 Animator 값 → 공격 애니메이션 순서입니다.
- `FixedUpdate`: 물리 이동·점프·대시 처리 후 공격 레이어를 갱신합니다.
- `PlayerAttack.LateUpdate`: 이번 프레임의 조준 방향이 확정된 뒤 실제 총알과 Spark를 발사합니다.

입력키는 방향키 이동, C 점프, X 대시, Z 고정 조준, 왼쪽 Shift 공격으로 동일합니다.

## 검증

`Tools/Validation`의 검증 코드는 Unity Editor Play 모드에서 Pipeline의 `script_run`으로 실행합니다. Unity Test Runner용 어셈블리나 런타임 의존성은 추가하지 않았습니다.

- `PlayerMovementChecks.Run`: 좌우 이동, 방향 반전, 앉기·앉은 공격, 8방향 고정 조준, 짧은 점프, 지상·공중 대시와 재사용 제한.
- `PlayerAttackChecks.Run`: 8방향 총알, Spark 회전·종료, 플레이어 충돌 무시, 얇은 벽 충돌과 Hit 프레임·접촉 위치, 거리·시간 제한, 풀 재사용, 연속 발사·키 해제.
- `SceneChecks.Run`: 최초 씬 종류 조회, Loading 장면에서 BotanicPanic으로 이동.

변경 전후 물리 검증값은 동일했습니다.

| 항목 | 변경 전후 |
|---|---|
| 이동 속도 | 5 |
| 검증용 바닥에서 5 물리 프레임 이동 거리 | 약 0.421520 — 바닥 마찰 포함 |
| 점프 시작 속도 | 30 |
| 점프키 해제 시 속도 비율 | 0.7 |
| 지상·공중 대시 거리 | 약 3.598567 |
| 발사 간격 | 0.12초 |

가상 키 입력을 각 입력 처리 메서드에 전달하는 검증이므로 OS 포커스와 실제 키보드 입력은 별도 확인이 필요합니다. 프레임률·마찰에 따른 실제 플레이 느낌은 숫자 검증만으로 확정하지 않습니다.

## 에디터 수동 확인

1. Game 창을 선택하고 방향키/C/X 조작감과 점프 높이를 확인합니다.
2. Z로 8방향을 조준하고 Shift 공격, 앉은 공격, 이동 공격을 확인합니다.
3. 대시 중 공격이 중단되고, 공중 대시가 착지 전 한 번만 가능한지 확인합니다.
4. Ground·Wall에서 Death 이펙트의 보이는 위치와 Spark 크기를 확인합니다.
5. Inspector의 ShootPos·BulletPool 참조와 기존 수치를 확인합니다.

플랫폼 빌드와 장시간 실기 플레이·프로파일링은 수행하지 않았습니다. 검증 범위는 Editor 컴파일, Play 모드의 자동 확인, 저장된 에셋 무결성입니다.

최종 확인에서 컴파일 오류와 게임 콘솔 오류는 0개였습니다. Pipeline 도구 자체의 통계 기록에서 문자열 인코딩 경고가 발생했으며, 검증은 정상 완료됐습니다. 이 경고를 없애기 위해 외부 패키지 코드는 수정하지 않았습니다.
